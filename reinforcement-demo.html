How this works, and what's still pending

Seeded, not randomly live. The dissertation's model is stochastic by design — it takes thousands of runs for a pattern to become reliable, and a single unrepeatable run is closer to noise than to a finding. So this playback isn't sampling fresh randomness on every visit: each agent's tick-by-tick path is generated from a fixed seed (2026 + agent_id × 97, one seed per agent, hard-coded), using the same step-by-step sampling logic the real model uses. Re-running the simulation, reloading the page, or rebuilding the site all reproduce the identical run — nothing here is re-randomized.

What's real here already: each agent's full transition odds — not just whether it persists, but where it goes if it doesn't — are pulled directly from the dissertation's transition-probability table, split by attribute and current state: for example an agent diagnosed with depression currently positive has a 71.6% chance of staying positive, 10.1% neutral, 18.3% negative on its next post (n=454); one currently negative is 58.5% negative / 14.2% neutral / 27.3% positive (n=289); not-diagnosed agents run 64.7% positive-persistence (n=405) and 64.6% negative-persistence (n=384) with the remainder split the same way. The table breaks these down further by how much post history the model has for an agent — those conditioned rows aren't extra data, they're the same observations sliced more finely, so the figures above use the unconditioned count for each cell rather than adding the slices together. Two other mechanics are also real, taken directly from the NetLogo source rather than the probability table: agents only transition on ticks they actually post (a real, attribute- and state-specific posting probability gates every tick), and an agent that goes more than 20 ticks without posting is hard-reset to neutral regardless of anything else.

What's still illustrative, and why: the one figure that isn't pulled from a real number is the size of the connection effect itself — how much a shared-sentiment tie boosts persistence. I did run the matched comparison directly (same memory-model tier, no pooling across configurations): agents with at least one same-sentiment neighbour, against isolated agents, state by state. It doesn't support a specific number — the connected-agent sample is tiny (11–21 observations per attribute/state, one cell has only 1) and inconsistent in direction (4 of 6 cells persist less when connected, not more), and pooled across all six, connected agents persisted very slightly less than isolated ones (59.6% vs. 61.8%, n=52 vs. n=1,723) — the opposite of the dissertation's claim, though well within noise at that sample size. So the demo applies a modest, clearly-labeled placeholder boost instead, using the same proportional-redistribution technique the model itself uses elsewhere (its neutral-threshold intervention), chosen only to guarantee the correct direction that the dissertation's full, thousands-of-runs simulation reports: connected agents persist somewhat more than isolated ones, so isolated agents visibly switch states more often over the course of a run. This raw transition-probability export just doesn't have enough same-sentiment-neighbour observations to confirm that finding on its own — it isn't a substitute for re-running the actual model.

Network and agents: the group's shape — who has many ties, who has few, the mix of one-directional and mutual ties — mirrors the real seed network's structure, but every agent shown is synthetic, with no one-to-one mapping to actual participants.
